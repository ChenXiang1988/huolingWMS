# wms/owner-access Specification

## Purpose

货主从两个入口进来：系统对接走 API，人工操作走自助端。这个能力定的是"谁能进来、进来能干什么、身份从哪来"，以及两个入口必须共用同一套业务规则，不允许出现两边校验不一致。

## Requirements

### Requirement: 对外接口规范由本系统定义并版本化

系统 SHALL 以本系统为准定义货主接口的报文结构、错误码与调用约定，对外发布可接入的规范版本。

#### Scenario: 货主按规范接入

- **WHEN** 货主方系统按已发布规范调用下单与查询接口
- **THEN** 无需本系统改代码即可完成对接
- **AND** 规范中列出的错误码有明确含义

#### Scenario: 已发布规范的变更

- **WHEN** 需要调整已发布接口的报文语义
- **THEN** 发布新版本
- **AND** 旧版本保留过渡期，不就地改语义

#### Scenario: 货主要求按其现有格式定制

- **WHEN** 货主希望接口照搬其现有系统的报文结构
- **THEN** 由对方改造或在我方之外加适配层解决
- **AND** 不改动我方对外规范的语义

### Requirement: 货主身份由入口决定，与请求内容无关

系统 SHALL 从入口凭据推导货主身份：API 取凭证绑定的货主，自助端取登录账号绑定的货主。

#### Scenario: API 建单

- **WHEN** 货主通过 API 创建单据
- **THEN** 单据货主等于凭证绑定的货主
- **AND** 请求体中出现其他货主标识时不生效或直接拒绝

#### Scenario: 自助端建单

- **WHEN** 货主账号（无论是主账号还是子账号）在自助端创建单据
- **THEN** 单据货主等于该账号绑定的货主
- **AND** 界面上不提供货主选择项

#### Scenario: 尝试写入他人数据

- **WHEN** 货主身份尝试读取或修改属于其他货主的数据
- **THEN** 请求被拒绝
- **AND** 返回结果不泄露该数据是否存在

### Requirement: 货主账号分主账号与子账号

系统 SHALL 为每个货主维持且仅维持一个主账号。主账号可在本货主下创建子账号并为其指定可用范围；子账号不能创建账号，也不能跨货主。

#### Scenario: 一个货主只有一个主账号

- **WHEN** 为某货主开户
- **THEN** 生成唯一主账号
- **AND** 再次为该货主开户被拒绝

#### Scenario: 主账号创建子账号

- **WHEN** 主账号创建子账号
- **THEN** 子账号归属同一个货主
- **AND** 可指定子账号是操作员还是只读

#### Scenario: 子账号不能建号

- **WHEN** 子账号尝试创建账号
- **THEN** 请求被拒绝

#### Scenario: 不能把子账号建到别家货主下

- **WHEN** 主账号创建子账号
- **THEN** 子账号的货主取自创建者的货主
- **AND** 请求体中指定其他货主不生效或直接拒绝

#### Scenario: 主账号不能自我清除

- **WHEN** 主账号尝试停用或删除自己
- **THEN** 请求被拒绝
- **AND** 提示该操作需由仓库侧执行，避免货主失去管理入口

#### Scenario: 子账号被停用后立即失效

- **WHEN** 主账号停用某个子账号
- **THEN** 该子账号已有的登录态立即失效
- **AND** 后续请求被拒绝

### Requirement: 密码自助修改与主账号重置并存

系统 SHALL 允许账号凭原密码自助修改密码，同时允许货主主账号直接重置本货主子账号的密码。

#### Scenario: 自助改密码

- **WHEN** 账号提交原密码与新密码
- **THEN** 校验通过后密码更新
- **AND** 之后用新密码登录成功、旧密码失败

#### Scenario: 原密码错误

- **WHEN** 提交的原密码与当前密码不符
- **THEN** 请求被拒绝
- **AND** 不泄露当前密码的任何信息

#### Scenario: 主账号重置子账号密码

- **WHEN** 主账号为子账号设置新密码
- **THEN** 无需原密码即可生效
- **AND** 该子账号之后的登录使用新密码

#### Scenario: 子账号不能重置他人

- **WHEN** 子账号尝试重置其他账号的密码
- **THEN** 请求被拒绝
- **AND** 子账号只能改自己的密码且需提供原密码

#### Scenario: 主账号忘记密码

- **WHEN** 主账号自己忘记密码
- **THEN** 由仓库侧重置
- **AND** 主账号不能在不提供原密码的情况下重置自己

### Requirement: 需要立即切断访问时应停用账号

系统 SHALL 让账号停用立即生效，而密码重置只改变后续登录凭据，不追溯已签发的会话。

#### Scenario: 停用后旧会话立即失效

- **WHEN** 主账号停用某个子账号
- **THEN** 该子账号已持有的会话在下一次请求时被拒绝
- **AND** 不需要等待会话自然过期

#### Scenario: 重置密码不回溯会话

- **WHEN** 主账号重置子账号密码
- **THEN** 已签发的会话在过期前仍可用
- **AND** 界面上把"停用账号"与"重置密码"并列呈现，需要立即切断时提示用停用

### Requirement: 子账号的可用功能由授予范围决定

系统 SHALL 让主账号与子账号的数据可见范围一致（同一货主），功能可用范围按授予的角色区分。

#### Scenario: 只读子账号

- **WHEN** 只读子账号登录
- **THEN** 可查询库存、单据进度与账单
- **AND** 不能创建任何单据

#### Scenario: 操作员子账号

- **WHEN** 操作员子账号登录
- **THEN** 可创建入库预报与出库订单
- **AND** 不能管理子账号

#### Scenario: 数据范围不因角色变化

- **WHEN** 主账号与任一子账号查询同一类数据
- **THEN** 看到的是同一个货主的数据集
- **AND** 差异只在能否执行写操作

### Requirement: 两个入口共用同一套业务规则

系统 SHALL 让 API 与自助端调用同一份建单与校验实现，不各自维护一套。

#### Scenario: 两个入口提交相同内容

- **WHEN** 同一张单据分别通过 API 与自助端提交相同内容
- **THEN** 校验结果、单号规则、幂等行为完全一致

#### Scenario: 校验规则调整

- **WHEN** 某个必填项或校验规则发生变化
- **THEN** 两个入口同时生效
- **AND** 不存在只改一侧的情况

### Requirement: 自助端只呈现属于该货主的内容

系统 SHALL 让货主账号登录后只见自助端菜单与被授权的功能，看不到仓库内部作业模块。

#### Scenario: 货主账号的可见范围

- **WHEN** 货主账号登录
- **THEN** 侧边栏只有自助端菜单
- **AND** 直接访问仓库内部路由被拒绝

#### Scenario: 仓库员工不被当成货主

- **WHEN** 未绑定货主的员工登录
- **THEN** 进入后台而非自助端
- **AND** 可查看全部货主数据

#### Scenario: 自助端能力范围

- **WHEN** 货主在自助端操作
- **THEN** 能力限于建单、查库存、查单据进度、查账单、管理子账号
- **AND** 不能操作库位管理、任务执行、盘点等仓库内部功能

#### Scenario: 子账号不见账号管理入口

- **WHEN** 子账号登录
- **THEN** 侧边栏不出现子账号管理入口
- **AND** 直接访问该入口被拒绝

### Requirement: 自助端菜单随所属域停用而收起

系统 SHALL 让自助端的每个功能入口归属于对应的业务域，域被停用时该入口一并消失。

#### Scenario: 停用出库域

- **WHEN** 停用出库域
- **THEN** 自助端的出库单入口消失
- **AND** 货主调用出库相关接口得到明确的下线提示而非报错堆栈

#### Scenario: 停用主数据域

- **WHEN** 停用主数据域
- **THEN** 自助端整体不可用
- **AND** 因为货主身份与商品档案都来自主数据域

### Requirement: 凭证可撤销、可过期、明文只出现一次

系统 SHALL 支持按凭证单独停用与设置有效期，凭证明文只在创建时展示一次。

#### Scenario: 停用某一张凭证

- **WHEN** 管理员停用某个货主的某张凭证
- **THEN** 该凭证立即失效
- **AND** 该货主的其他凭证不受影响

#### Scenario: 凭证过期

- **WHEN** 凭证超过有效期
- **THEN** 调用被拒绝并明确提示已过期
- **AND** 不按无效凭证的模糊提示处理

#### Scenario: 明文不可再看

- **WHEN** 凭证创建完成后再次查看
- **THEN** 只能看到前缀标识
- **AND** 无法取回明文

### Requirement: 单据记录来源入口

系统 SHALL 在单据上记录创建来源是 API 还是自助端，以及对应的操作者身份。

#### Scenario: 追溯创建来源

- **WHEN** 查看任意一张货主创建的单据
- **THEN** 可看到来源入口与操作者
- **AND** API 创建的单据能定位到具体凭证

### Requirement: 货主门户与后台是两个独立登录端

系统 SHALL 把货主门户与管理后台做成两个独立的登录端：入口分开、登录页分开、登录时就判定账号身份，跨端访问直接失败而不是重定向。

三层都要分开，只分界面不算分开：

| 层次 | 要求 |
|---|---|
| 入口 | 后台在 `/admin/`，门户在 `/owner/`，各自独立的构建产物与 `index.html` |
| 登录 | 两个登录接口，各自只接受本端账号；身份不符在登录这一步失败 |
| 会话 | 同一套 JWT，但每个入口只认自己那类账号，跨端清会话回本端登录页 |

#### Scenario: 货主账号尝试从后台登录

- **WHEN** 绑定了货主的账号在后台登录接口提交凭据
- **THEN** 登录被拒绝，提示该账号属于货主方、应使用货主门户
- **AND** 不签发任何 token

#### Scenario: 员工账号尝试从门户登录

- **WHEN** 未绑定货主的账号在门户登录接口提交凭据
- **THEN** 登录被拒绝，提示应使用管理后台
- **AND** 不签发任何 token

#### Scenario: 货主账号正常登录门户

- **WHEN** 绑定了货主的有效账号从门户登录
- **THEN** 登录成功并进入门户首页
- **AND** 后台的任何页面都不在其可达范围内

#### Scenario: 拿错端的 token 访问

- **WHEN** 用员工 token 打开门户页面，或用货主 token 打开后台页面
- **THEN** 该端清空会话并回到本端登录页
- **AND** 不跳到另一端，也不出现"先进入再被送走"

#### Scenario: 凭据错误不泄露账号是否存在

- **WHEN** 门户登录使用不存在的账号或错误密码
- **THEN** 两种情况返回同一句提示
- **AND** 不通过错误信息区分"账号不存在"与"密码错误"

#### Scenario: 两端产物互不兜底

- **WHEN** 请求后台路径下不存在的子路由
- **THEN** 回退到后台自己的入口文件
- **AND** 不会回退到门户的入口文件

### Requirement: 自助端界面外壳可与后台共享而不合并身份

系统 SHALL 允许货主自助端复用管理后台的侧栏、顶栏、主题与国际化外壳，同时保持入口、登录接口、登录页与会话判定各自独立。

#### Scenario: 共享外壳后仍能区分两端

- **WHEN** 货主账号从 `/owner/` 登录并看到与后台一致的侧栏与顶栏
- **THEN** 侧栏只呈现该账号被授权的 `/owner` 菜单
- **AND** 仓库内部模块与后台路由仍不在其可达范围内

#### Scenario: 共享外壳不改变跨端会话判定

- **WHEN** 员工 token 访问自助端或货主 token 访问后台
- **THEN** 该端清空会话并回到本端登录页
- **AND** 不因为组件相同而放行另一类账号

#### Scenario: 登录页保持独立

- **WHEN** 未登录用户访问 `/owner/login`
- **THEN** 显示货主门户自己的品牌登录页
- **AND** 不复用后台登录页视觉或后台登录接口

### Requirement: 自助端能力覆盖规格承诺的全部页面

系统 SHALL 让货主自助端提供建单、查库存、查单据进度、查账单、创建本货主商品档案与管理子账号的入口，各入口按账号角色授权可见。

#### Scenario: 主账号可见能力

- **WHEN** 货主主账号登录自助端
- **THEN** 可见概览、库存查询、账单查询、商品档案、入库预报、出库订单与子账号管理
- **AND** 每个入口只展示或写入本货主的数据

#### Scenario: 操作员子账号可见能力

- **WHEN** 操作员子账号登录自助端
- **THEN** 可见概览、库存查询、账单查询、商品档案、入库预报与出库订单
- **AND** 不出现子账号管理入口

#### Scenario: 只读子账号可见能力

- **WHEN** 只读子账号登录自助端
- **THEN** 可见概览、库存查询、账单查询、商品档案与单据进度
- **AND** 不出现任何创建或管理入口，直接访问创建接口被拒绝

### Requirement: 货主在自助端创建商品档案时只提交本侧字段

系统 SHALL 让货主在自助端创建属于本货主的商品档案，只提交货主负责的"这是什么货"字段；仓库侧"这货怎么存"的字段不出现在自助端，也不接受自助端写入。

#### Scenario: 货主创建商品

- **WHEN** 有建单权限的货主账号在自助端提交商品档案
- **THEN** 商品归属取自会话绑定的货主
- **AND** 请求体中的其他货主标识不生效或被拒绝

#### Scenario: 字段分工

- **WHEN** 货主在自助端填写商品档案
- **THEN** 界面与请求只包含编码、名称、规格、条码、批次开关等货主侧字段
- **AND** 上架要求、温区、库位策略等仓库侧字段不在界面出现且不因该请求改变

#### Scenario: 只读账号不能创建

- **WHEN** 只读子账号尝试创建商品档案
- **THEN** 请求被拒绝
- **AND** 界面不显示创建入口

#### Scenario: 商品列表只含本货主

- **WHEN** 货主查看自助端商品列表
- **THEN** 只返回本货主的商品
- **AND** 不同货主的同名商品彼此独立

### Requirement: 自助端每个入口归属于自己的业务域

系统 SHALL 让自助端顶级目录保留主数据域归属，同时让其下每个功能入口按自己的业务域打归属标签，使该域停用时只有该入口收起，其他入口不受影响。

#### Scenario: 停用库存域

- **WHEN** 仓库停用库存域
- **THEN** 自助端的库存查询入口消失
- **AND** 概览、商品档案、入库预报、出库订单入口仍在

#### Scenario: 停用出库域

- **WHEN** 仓库停用出库域
- **THEN** 自助端的出库订单入口消失
- **AND** 后台侧栏不因此出现门户菜单

#### Scenario: 停用主数据域

- **WHEN** 仓库停用主数据域
- **THEN** 整个自助端不可用
- **AND** 因为顶级目录与商品档案都归主数据域

#### Scenario: 入口归属不影响货主可见性

- **WHEN** 域归属标签按业务域修正后货主登录
- **THEN** 货主看到的菜单名称、顺序与页面内容不变
- **AND** 仍只看到被授权的那一部分入口

### Requirement: 自助端录入与查询在交互上分离

系统 SHALL 让自助端每个既录入又查询的页面默认只呈现查询视图，录入通过右侧抽屉承载，提交后关闭抽屉并刷新查询结果。

#### Scenario: 列表页默认不含常驻表单

- **WHEN** 货主打开商品档案或出库订单页面
- **THEN** 页面只显示列表与筛选条件
- **AND** 不出现常驻的输入表单

#### Scenario: 通过抽屉录入

- **WHEN** 货主点击「新建」类按钮
- **THEN** 右侧抽屉打开并显示录入表单
- **AND** 抽屉有关闭与取消入口，未提交时不改动列表

#### Scenario: 提交后的反馈

- **WHEN** 货主在抽屉中提交成功
- **THEN** 抽屉关闭、列表刷新出新记录
- **AND** 货主能明确看到提交结果与新单据/商品的信息

#### Scenario: 提交失败

- **WHEN** 抽屉中提交被服务端拒绝
- **THEN** 抽屉保持打开并显示错误原因
- **AND** 已填内容不丢失

### Requirement: 货主可查看自己提交的入库预报

系统 SHALL 让货主在自助端查看本货主提交的入库预报列表与详情，范围由会话绑定的货主决定。

#### Scenario: 查看预报列表

- **WHEN** 货主打开入库预报页面
- **THEN** 显示本货主已提交的预报列表，含单号、货主单号、状态、预计到货与提交时间
- **AND** 不显示其他货主的预报

#### Scenario: 预报详情

- **WHEN** 货主点击某条预报
- **THEN** 显示该预报的明细行与状态
- **AND** 其他货主的预报不可通过直接访问标识取得

#### Scenario: 提交后定位到新记录

- **WHEN** 货主提交一张新预报成功
- **THEN** 抽屉关闭、列表刷新且新记录可见
- **AND** 货主不需要重新进入页面就能找到刚提交的单据
