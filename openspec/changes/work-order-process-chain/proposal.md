# Proposal

## Why

现有系统的作业由货主单据（ASN、出库订单）或库内作业单直接触发，一张单据内部的状态机是扁平推进的。对标仓库的真实做法是一张客户单据或仓库自建单据生成一条工单，工单按工序链拆成到货签到、验货、收货、上架等有前后置关系的多道工序，工序再生成任务派到 PDA。现有规格没有工单概念，也没有工序定义、前后置与跳序拦截，无法表达这种"单据 → 工序 → 任务"的三层结构。这是后续任务派工、到货签到两项能力的基础层，先立起来才不会各做各的。

## What Changes

- 新增能力 `wms/work-order-process-chain`：仓库自建工单与工序链编排。
- 引入"工单"这一单据类型：由客户单据或仓库员工自建，绑定唯一货主，持有一条工序链与当前进度；工单本身不改业务域状态，只通过工序完成事件驱动既有域状态机推进。
- 工序链可配置：定义工序类型、前后置关系、每道工序的完成条件；上一工序未完成不得启动下一工序。
- 一张工单可按货主、商品或数量拆成多条子工单并行执行，子工单完成后汇总回父工单。
- 工序完成走 `transit` 迁移边校验，不在接口里直接改单据状态。
- **BREAKING**：无。现有单据与状态机不变，本变更只新增编排层。

## Capabilities

### New Capabilities

- `wms/work-order-process-chain`: 仓库自建工单与工序链的编排能力——工单建模、工序定义与前后置、跳序拦截、子工单拆分与汇总。

### Modified Capabilities

无。不修改 8 份常驻规格的任何 Requirement；本能力作为编排层叠加在既有域之上。

## Impact

- 新增工单编排层，作为独立插件包或任务域内的编排模块（落点在 design.md 定）。
- 复用既有 `register_handler` 契约承接工序完成后的业务动作，不重写入库/出库/库内作业域的状态机。
- 新增工单表、工序定义表、工序实例表；跨域引用按 D6 存 id + code，不建外键。
- 新增权限标识 `wms_work_order:*`；新增单号前缀与工单幂等键。
- 依赖后续 `task-dispatch-split` 把工序转成可派工任务，本次只定义工序到任务的接入契约，不实现派工。
