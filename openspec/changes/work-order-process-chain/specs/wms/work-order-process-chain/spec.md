# Spec Delta

## Purpose

让仓库能把一张客户单据或自建单据编排成有前后置关系的工序链，工序完成再驱动既有业务域推进。编排层只持有工序与进度，不替代各域自己的状态机与记账契约，避免一张工单同时改写多个域的状态而破坏域归属。

## ADDED Requirements

### Requirement: 工单绑定唯一货主且来源可追溯
系统 SHALL 让每张工单绑定唯一货主，并记录来源单据与创建入口；工单下全部工序与子工单同属该货主。

#### Scenario: 客户单据生成工单
- **WHEN** 货主提交一张 ASN 或出库订单并启用工序编排
- **THEN** 生成一张工单，货主取自来源单据，记录来源单据类型与标识
- **AND** 工单下全部工序的货主与来源单据一致

#### Scenario: 仓库员工自建工单
- **WHEN** 仓库员工为某货主创建一张工单
- **THEN** 工单绑定该货主，创建来源标记为仓库自建
- **AND** 员工账号本身未绑定货主不影响工单的货主归属

#### Scenario: 跨货主合并被拒绝
- **WHEN** 试图把两个货主的来源单据放进同一张工单
- **THEN** 提交被拒绝并提示按货主拆单

#### Scenario: 引用未建档商品被拒绝
- **WHEN** 工单明细引用该货主下不存在的商品
- **THEN** 创建被拒绝并提示先建档，不在建单过程中自动创建商品

### Requirement: 工单是编排层不改写业务域状态
系统 SHALL 使工单只持有工序链与进度，业务域状态与库存数量仍由各域自己的状态机与记账契约管理。

#### Scenario: 工序完成驱动业务推进
- **WHEN** 一道工序完成
- **THEN** 通过注册的处理器调用对应业务域的既有接口推进状态或记账
- **AND** 工单只更新自身的工序进度，不直接改写业务单据的状态字段

#### Scenario: 业务域失败则工序不完成
- **WHEN** 工序完成时业务域接口返回失败
- **THEN** 该工序保持未完成，工单进度不推进
- **AND** 不产生只改了工单进度却没改业务单据的中间状态

#### Scenario: 工单停用不影响既有单据
- **WHEN** 停用工序编排能力
- **THEN** 货主仍可按原有方式经 API 或自助端建单，业务单据不依赖工单存在

### Requirement: 工序链按可配置的前后置关系流转
系统 SHALL 让每张工单按一条工序链执行，工序类型、顺序与前后置关系可配置，上一工序未完成不得启动下一工序。

#### Scenario: 入库工序链按序执行
- **WHEN** 一张入库工单配置为到货签到、验货、收货、上架四道工序
- **THEN** 四道工序按配置顺序依次变为可执行
- **AND** 未完成的工序不因前序跨越而提前开放

#### Scenario: 跳序被拦截
- **WHEN** 尝试在验货工序完成前启动收货工序
- **THEN** 请求被拒绝并指出缺失的前置工序
- **AND** 不产生该工序的任务或业务状态变化

#### Scenario: 多前置全部满足才可启动
- **WHEN** 一道工序声明了两个前置工序
- **THEN** 两个前置都完成后该工序才变为可执行
- **AND** 只完成其中一个时仍保持锁定

#### Scenario: 工序链按单据类型区分
- **WHEN** 出库工单与入库工单分别定义工序链
- **THEN** 各自按所属链路流转，不混用对方的工序定义
- **AND** 同一时刻一张工单只走一条工序链

#### Scenario: 无前置的工序可并行
- **WHEN** 两条工序都没有前置且不互相依赖
- **THEN** 两条工序可同时进入可执行状态
- **AND** 各自的完成互不阻塞对方

### Requirement: 工序完成条件可判定且可追溯
系统 SHALL 为每道工序定义明确的完成条件，并记录每道工序的开始与完成时间、执行人及结果。

#### Scenario: 满足完成条件才关闭工序
- **WHEN** 一道工序的执行结果不满足其完成条件
- **THEN** 工序保持进行中，不推进到下一道
- **AND** 记录未通过的原因

#### Scenario: 工序执行可追溯
- **WHEN** 查看一张工单的工序流水
- **THEN** 能看到每道工序的开始时间、完成时间、执行人、结果与来源任务
- **AND** 能定位到工序对应的业务动作

#### Scenario: 工单进度按工序汇总
- **WHEN** 查询工单进度
- **THEN** 返回已完成工序数、总工序数与当前可执行的工序
- **AND** 进度只对当前货主可见

### Requirement: 工单可拆子工单并行并汇总
系统 SHALL 支持一张工单按商品或数量拆成多条子工单并行执行，子工单完成后汇总回父工单。

#### Scenario: 按商品拆子工单
- **WHEN** 一张工单含多个商品且需要并行处理
- **THEN** 按商品拆成多条子工单，各带独立工序链
- **AND** 子工单的货主与父工单一致

#### Scenario: 按数量拆子工单
- **WHEN** 一道工序的货量超过单批处理上限
- **THEN** 按数量拆成多条子工单分批执行
- **AND** 各子工单数量之和等于父工单数量

#### Scenario: 子工单完成汇总
- **WHEN** 全部子工单完成
- **THEN** 父工单按配置进入完成状态
- **AND** 父工单的汇总数量等于各子工单之和

#### Scenario: 子工单失败不关闭父工单
- **WHEN** 存在未完成或失败的子工单
- **THEN** 父工单保持进行中并标出未完成的子工单
- **AND** 不把失败子工单的数量计入已完成汇总

#### Scenario: 作废父工单连带子工单
- **WHEN** 一张未完成的父工单被作废
- **THEN** 其下全部未完成的子工单一并作废
- **AND** 已完成的子工单保留历史

### Requirement: 工序到任务以契约衔接
系统 SHALL 让可执行工序通过既有任务契约生成任务，工序本身不直接指定执行人。

#### Scenario: 工序生成任务
- **WHEN** 一道工序进入可执行状态且配置为任务驱动
- **THEN** 按工序类型生成一条任务，任务携带工序标识与来源工单标识
- **AND** 同一工序实例只生成一条未完成任务

#### Scenario: 任务完成后回写工序
- **WHEN** 任务被提交完成
- **THEN** 通过注册的处理器回写工序结果，工序按完成条件判断是否关闭
- **AND** 不重写业务域的状态机

#### Scenario: 工序非任务驱动
- **WHEN** 一道工序配置为系统自动执行
- **THEN** 由系统直接执行其业务动作并关闭工序
- **AND** 不生成待领取任务

#### Scenario: 接入既有任务去重
- **WHEN** 同一工序重复触发生成任务
- **THEN** 已存在未完成任务时不再生成第二条
- **AND** 复用既有任务的来源去重规则
