# Spec Delta

## Purpose

把散落在常驻规格与各期变更里的可观察行为集中成一份可执行的验收场景清单。每条场景对应一次可复现的操作与一个明确期望，作为上线门禁与回归的判定依据；本能力只收纳场景，不定义新行为，场景的权威表述仍在各自来源规格。

## ADDED Requirements

### Requirement: 平台基座验收场景
系统 SHALL 满足下列初始化与运行时约束场景（来源：`wms/platform-bootstrap`，p0-bootstrap）。

#### Scenario: 空环境首次初始化
- **WHEN** 数据库为空且执行初始化
- **THEN** 建出全部基座表、货灵角色基线，并生成一个可登录的超级管理员

#### Scenario: 重复执行
- **WHEN** 已初始化过的环境再执行一次初始化
- **THEN** 不重复建角色、不重复建菜单、不重置管理员密码，并提示已初始化

#### Scenario: 缺少必要配置
- **WHEN** 数据库连接或 JWT 密钥等关键配置缺失
- **THEN** 初始化中止并明确指出缺哪一项，不使用默认值静默继续

#### Scenario: 排序规则不符
- **WHEN** 数据库排序规则不是 `utf8mb4_0900_ai_ci`
- **THEN** 启动失败并提示实际值，不带着错误排序规则继续运行

#### Scenario: 时区不符
- **WHEN** 数据库会话时区不是 `+08:00`
- **THEN** 启动失败并提示，不按服务器本地时区静默运行

#### Scenario: 多 worker 启动
- **WHEN** 以多进程方式启动
- **THEN** 启动失败并说明插件状态不支持多进程，不允许各进程各自维护一份状态

#### Scenario: 全新环境登录
- **WHEN** 超级管理员首次登录
- **THEN** 侧边栏只有已启用业务域的顶级目录，不含基座示例、插件市场与组件演示菜单

#### Scenario: 未启用的能力菜单
- **WHEN** MCP 与 AI 助手保持关闭
- **THEN** 对应菜单不出现，但菜单记录保留，改状态即可恢复

#### Scenario: 门户菜单根
- **WHEN** 查看菜单表
- **THEN** 存在一个门户顶级目录，其权限归属主数据域，停用主数据域时一并收起

#### Scenario: 启用空插件
- **WHEN** 启用某个只含骨架的插件
- **THEN** 该域菜单可见，且不因尚未实现业务而报错

#### Scenario: 停用插件
- **WHEN** 停用某个域
- **THEN** 该域全部菜单不可见，接口对非超管返回未授权

#### Scenario: 依赖未满足
- **WHEN** 启用一个声明了前置依赖的插件而前置域未启用
- **THEN** 启用被拒绝并指出缺失的前置域，不进入半启用状态

#### Scenario: 角色清单
- **WHEN** 初始化完成
- **THEN** 存在超管与货主三级角色（主账号、操作员、只读），其余岗位角色随业务菜单就绪再建

#### Scenario: 按钮级权限
- **WHEN** 查看任一业务菜单
- **THEN** 其下挂着新增、编辑、删除、确认、取消等按钮级权限标识，格式符合约定

#### Scenario: 货主账号登录
- **WHEN** 账号绑定了货主
- **THEN** 落到门户首页，侧边栏是门户菜单，直接访问后台路由被拒绝

#### Scenario: 员工账号登录
- **WHEN** 账号未绑定货主
- **THEN** 落到后台首页，可查看全部货主数据

#### Scenario: 落点判断不依赖核心代码
- **WHEN** 前端需要知道账号是否货主
- **THEN** 通过业务域提供的接口获取，不修改基座的用户信息接口

### Requirement: 域边界与主数据验收场景
系统 SHALL 满足下列域归属、依赖关系与单仓多货主场景（来源：`wms/domain-map`）。

#### Scenario: 新能力落在唯一域
- **WHEN** 提出一个新业务能力
- **THEN** 蓝图给出唯一归属域；若同时改变两个域的状态则拆成两个能力

#### Scenario: 无归属时不塞进现有域
- **WHEN** 逐一比对十域职责后仍无匹配
- **THEN** 作为新域候选提出并修订蓝图，不塞进相邻域

#### Scenario: 相邻域不发生职责重叠
- **WHEN** 判定某能力属于库内作业还是入库
- **THEN** 依据是它是否改变物料在仓内的位置或账面数量，而非由哪个岗位操作

#### Scenario: 验货不是质检
- **WHEN** 处理到货核对
- **THEN** 归入库域的收货环节，不另建质检单据、不设检验结论，核对结果记为应收、实收、破损与差异原因

#### Scenario: 货主服务订单归入库域
- **WHEN** 货主就某次来货提出留样要求
- **THEN** 该单据归入库域，与入库预报是两份东西

#### Scenario: 留样记录归库内作业
- **WHEN** 判定实际划出的留样归哪个域
- **THEN** 归库内作业域，留样记录只存来源单据标识，不反向读取入库域的表

#### Scenario: 货主建货品基础信息
- **WHEN** 货主创建货品档案
- **THEN** 可填编码、名称、规格、单位、分类、重量体积、温区、条码，不能填上架优先库区等存储字段，创建后立即可建单无需审核

#### Scenario: 仓库补充存储要求
- **WHEN** 仓管员编辑货品档案
- **THEN** 可填上架优先库区、一托件数、上架要求，不改变货主已填的基础信息

#### Scenario: 引用未建档商品
- **WHEN** 建单时引用本货主下不存在的商品编码
- **THEN** 建单被拒绝并提示先建档，不在建单过程中自动创建商品

#### Scenario: 收货扫到未建档条码
- **WHEN** 收货扫码得到系统内不存在的条码
- **THEN** 该次扫描被拒绝并提示先建档，不自动创建商品档案

#### Scenario: 依赖声明形成闭环被拒绝
- **WHEN** 域 A 声明依赖域 B，而 B 的依赖链已包含 A
- **THEN** 该依赖声明不成立，需修改其中一方

#### Scenario: 强依赖未满足时拒绝启用
- **WHEN** 启用一个声明了前置依赖的域而前置域尚未启用
- **THEN** 启用被拒绝并明确给出缺失的前置域，不留下半启用状态

#### Scenario: 需要强一致时同步调用
- **WHEN** 入库域完成上架需要增加库存
- **THEN** 调用库存域公开的记账契约，数量变更与入库单据状态变更在同一事务提交

#### Scenario: 无需强一致时发布事件
- **WHEN** 两域联动允许延迟且不应互相阻断
- **THEN** 一方发布事件、另一方订阅，订阅方失败不回滚发布方已提交事务

#### Scenario: 禁用域后菜单整体消失
- **WHEN** 禁用出库域
- **THEN** 出库域全部菜单不可见，其接口对非超管返回未授权

#### Scenario: 重新启用后菜单恢复
- **WHEN** 重新启用该域
- **THEN** 原有菜单可见性与权限绑定恢复，无需重新配置角色

#### Scenario: 当期可独立验收
- **WHEN** 某一期关闭
- **THEN** 操作者无需等待后续期，即可在后台完成该期承诺的完整操作

#### Scenario: 后置能力不阻塞前序
- **WHEN** 任务域尚未交付
- **THEN** 入库与出库仍能由 PC 操作台直接执行，作业动作不因缺少任务单而无法记录

#### Scenario: 只有一条仓库记录
- **WHEN** 系统初始化完成
- **THEN** 存在且仅存在一条仓库记录，界面不提供仓库切换入口

#### Scenario: 越界仓库标识被拒绝
- **WHEN** 请求显式携带非本仓的仓库标识
- **THEN** 请求被拒绝，不静默按本仓处理

#### Scenario: 一张单据只属于一个货主
- **WHEN** 创建任意业务单据
- **THEN** 单据绑定唯一货主，单据下全部明细行同属该货主

#### Scenario: 货主不可跨单据合并
- **WHEN** 操作者试图把两个货主的明细放进同一张单据
- **THEN** 提交被拒绝并提示按货主拆单

#### Scenario: 货主下单
- **WHEN** 货主通过 API 或自助端创建入库单、出库单
- **THEN** 建单逻辑由入库域或出库域实现，不经过集成域转手

#### Scenario: 作业结果回传
- **WHEN** 作业结果需要推送给货主或上游平台
- **THEN** 由集成域发起，业务域不直接对外推送

#### Scenario: 扫错货主被拦截
- **WHEN** 在属于货主 A 的单据下扫描到货主 B 的商品
- **THEN** 该次扫描被拒绝并提示，不产生任何库存变动

#### Scenario: 扫错库位被拦截
- **WHEN** 扫描的库位与任务指定的库位不一致
- **THEN** 该次扫描被拒绝，作业进度不推进

#### Scenario: 扫错批次被拦截
- **WHEN** 拣货任务指定批次 A，扫描到的是同商品的批次 B
- **THEN** 该次扫描被拒绝，不允许用其他批次充数

#### Scenario: 共享库位混放不影响隔离
- **WHEN** 同一库位存放多个货主或多个批次的商品
- **THEN** 库存记录按货主与批次彼此独立，拣货只取出单据指定的货主与批次的数量

#### Scenario: 停用域不删除前端页面
- **WHEN** 停用某个域
- **THEN** 该域前端页面文件仍留在仓库中，只是菜单不生成、路由不注册、接口不可用

#### Scenario: 上传插件包不含前端
- **WHEN** 通过上传方式安装业务插件
- **THEN** 仅接受后端包，不承诺该域界面同时上线

### Requirement: 货主访问验收场景
系统 SHALL 满足下列货主身份、账号、凭证与双端隔离场景（来源：`wms/owner-access`，含 `split-owner-portal-entry` 与 `integrate-warehouse-network` 增量）。

#### Scenario: 货主按规范接入
- **WHEN** 货主方系统按已发布规范调用下单与查询接口
- **THEN** 无需本系统改代码即可完成对接，规范中的错误码有明确含义

#### Scenario: 已发布规范的变更
- **WHEN** 需要调整已发布接口的报文语义
- **THEN** 发布新版本，旧版本保留过渡期，不就地改语义

#### Scenario: 货主要求按其现有格式定制
- **WHEN** 货主希望接口照搬其现有系统的报文结构
- **THEN** 由对方改造或加我方之外的适配层，不改动我方对外规范语义

#### Scenario: API 建单
- **WHEN** 货主通过 API 创建单据
- **THEN** 单据货主等于凭证绑定的货主，请求体中的其他货主标识不生效或被拒绝

#### Scenario: 自助端建单
- **WHEN** 货主主账号或子账号在自助端创建单据
- **THEN** 单据货主等于账号绑定的货主，界面不提供货主选择项

#### Scenario: 尝试写入他人数据
- **WHEN** 货主身份尝试读取或修改其他货主的数据
- **THEN** 请求被拒绝，返回结果不泄露该数据是否存在

#### Scenario: 一个货主只有一个主账号
- **WHEN** 为某货主开户
- **THEN** 生成唯一主账号，再次为该货主开户被拒绝

#### Scenario: 主账号创建子账号
- **WHEN** 主账号创建子账号
- **THEN** 子账号归属同一货主，可指定为操作员或只读

#### Scenario: 子账号不能建号
- **WHEN** 子账号尝试创建账号
- **THEN** 请求被拒绝

#### Scenario: 不能把子账号建到别家货主下
- **WHEN** 主账号创建子账号时在请求体中指定其他货主
- **THEN** 子账号货主取自创建者，请求体中的其他货主不生效或被拒绝

#### Scenario: 主账号不能自我清除
- **WHEN** 主账号尝试停用或删除自己
- **THEN** 请求被拒绝，并提示需由仓库侧执行

#### Scenario: 子账号被停用后立即失效
- **WHEN** 主账号停用某个子账号
- **THEN** 该子账号已有登录态立即失效，后续请求被拒绝

#### Scenario: 自助改密码
- **WHEN** 账号提交原密码与新密码且校验通过
- **THEN** 密码更新，之后新密码登录成功、旧密码失败

#### Scenario: 原密码错误
- **WHEN** 提交的原密码与当前密码不符
- **THEN** 请求被拒绝，不泄露当前密码的任何信息

#### Scenario: 主账号重置子账号密码
- **WHEN** 主账号为子账号设置新密码
- **THEN** 无需原密码即可生效，该子账号之后用新密码登录

#### Scenario: 子账号不能重置他人
- **WHEN** 子账号尝试重置其他账号的密码
- **THEN** 请求被拒绝，子账号只能改自己的密码且需提供原密码

#### Scenario: 主账号忘记密码
- **WHEN** 主账号自己忘记密码
- **THEN** 由仓库侧重置，主账号不能在不提供原密码的情况下重置自己

#### Scenario: 停用后旧会话立即失效
- **WHEN** 主账号停用某个子账号
- **THEN** 该子账号已持有的会话在下一次请求时被拒绝，无需等待自然过期

#### Scenario: 重置密码不回溯会话
- **WHEN** 主账号重置子账号密码
- **THEN** 已签发会话在过期前仍可用，界面把停用账号与重置密码并列提示

#### Scenario: 只读子账号
- **WHEN** 只读子账号登录
- **THEN** 可查询库存、单据进度与账单，不能创建任何单据

#### Scenario: 操作员子账号
- **WHEN** 操作员子账号登录
- **THEN** 可创建入库预报与出库订单，不能管理子账号

#### Scenario: 数据范围不因角色变化
- **WHEN** 主账号与任一子账号查询同一类数据
- **THEN** 看到同一货主的数据集，差异只在能否执行写操作

#### Scenario: 两个入口提交相同内容
- **WHEN** 同一张单据分别通过 API 与自助端提交相同内容
- **THEN** 校验结果、单号规则、幂等行为完全一致

#### Scenario: 校验规则调整
- **WHEN** 某个必填项或校验规则发生变化
- **THEN** 两个入口同时生效，不存在只改一侧的情况

#### Scenario: 货主账号的可见范围
- **WHEN** 货主账号登录
- **THEN** 侧边栏只有自助端菜单，直接访问仓库内部路由被拒绝

#### Scenario: 仓库员工不被当成货主
- **WHEN** 未绑定货主的员工登录
- **THEN** 进入后台而非自助端，可查看全部货主数据

#### Scenario: 自助端能力范围
- **WHEN** 货主在自助端操作
- **THEN** 能力限于建单、查库存、查单据进度、查账单、管理子账号，不能操作仓库内部功能

#### Scenario: 子账号不见账号管理入口
- **WHEN** 子账号登录
- **THEN** 侧边栏不出现子账号管理入口，直接访问该入口被拒绝

#### Scenario: 停用出库域
- **WHEN** 停用出库域
- **THEN** 自助端出库单入口消失，货主调用出库接口得到明确下线提示而非报错堆栈

#### Scenario: 停用主数据域
- **WHEN** 停用主数据域
- **THEN** 自助端整体不可用

#### Scenario: 停用某一张凭证
- **WHEN** 管理员停用某个货主的某张凭证
- **THEN** 该凭证立即失效，该货主其他凭证不受影响

#### Scenario: 凭证过期
- **WHEN** 凭证超过有效期
- **THEN** 调用被拒绝并明确提示已过期，不按无效凭证的模糊提示处理

#### Scenario: 明文不可再看
- **WHEN** 凭证创建完成后再次查看
- **THEN** 只能看到前缀标识，无法取回明文

#### Scenario: 追溯创建来源
- **WHEN** 查看任意一张货主创建的单据
- **THEN** 可看到来源入口与操作者，API 创建的单据能定位到具体凭证

#### Scenario: 货主账号尝试从后台登录
- **WHEN** 绑定货主的账号在后台登录接口提交凭据
- **THEN** 登录被拒绝并提示应使用货主门户，不签发任何 token

#### Scenario: 员工账号尝试从门户登录
- **WHEN** 未绑定货主的账号在门户登录接口提交凭据
- **THEN** 登录被拒绝并提示应使用管理后台，不签发任何 token

#### Scenario: 货主账号正常登录门户
- **WHEN** 绑定货主的有效账号从门户登录
- **THEN** 登录成功并进入门户首页，后台任何页面不在其可达范围

#### Scenario: 拿错端的 token 访问
- **WHEN** 用员工 token 打开门户页面，或用货主 token 打开后台页面
- **THEN** 该端清空会话并回到本端登录页，不跳到另一端

#### Scenario: 凭据错误不泄露账号是否存在
- **WHEN** 门户登录使用不存在的账号或错误密码
- **THEN** 两种情况返回同一句提示，不区分账号不存在与密码错误

#### Scenario: 两端产物互不兜底
- **WHEN** 请求后台路径下不存在的子路由
- **THEN** 回退到后台自己的入口文件，不回退到门户入口文件

#### Scenario: 已接入上游的货主不建单
- **WHEN** 货主已接入上游且其开关开启
- **THEN** 自助端不提供手工建单入口

#### Scenario: 未接入上游的货主照常建单
- **WHEN** 货主未接入上游
- **THEN** 自助端建单入口照常可用

#### Scenario: 切换接入开关
- **WHEN** 货主的接入开关发生切换
- **THEN** 建单入口按新的接入状态立即生效

### Requirement: 入库验收场景
系统 SHALL 满足下列预报、收货、上架与异常处置场景（来源：`wms/domain-map`、`wms/lot-control`、`docs/design/inbound-walkthrough.md`，p2-inbound）。

#### Scenario: 预报与留样服务订单建单
- **WHEN** 货主调 API 建 ASN 与留样服务订单
- **THEN** ASN 直接为 `confirmed`、服务订单为 `confirmed` 且记录 `source=api`

#### Scenario: 门户建单先进草稿
- **WHEN** 货主在门户建 ASN
- **THEN** 先为 `draft`，提交后才推进，与 API 共用同一建单服务

#### Scenario: 一 ASN 挂多张收货单
- **WHEN** 分批到货，对同一 ASN 再开一张收货单
- **THEN** 生成新收货单、ASN 仍保持 `receiving`，累计实收按 ASN 汇总

#### Scenario: 验货生成收货单
- **WHEN** 仓管对确认的 ASN 点开始收货
- **THEN** ASN 转 `receiving`，生成 `open` 收货单，应收数量从 ASN 明细带入

#### Scenario: 一次收货拆多批次
- **WHEN** 一行应收对应多个生产批次
- **THEN** 按批号拆成多条收货明细，各批次数量之和等于实收总数

#### Scenario: 批号相同但效期不一致被拒
- **WHEN** 录入的批号已存在但生产日期或到期日与已有记录不一致
- **THEN** 整单收货被拒绝并提示核对，不产生该批次的库存

#### Scenario: 批号模糊无法识别
- **WHEN** 实物批号模糊且货主无法确认
- **THEN** 该行暂不收货、不入账，系统不产生记录

#### Scenario: 少收留 ASN 等待补货
- **WHEN** 实收小于应收
- **THEN** 按实收记差异原因为 `short`，ASN 留在 `receiving` 等补货或人工结案

#### Scenario: 超收拒绝
- **WHEN** 实收大于应收
- **THEN** 收货被拒绝，需货主追加 ASN 后重收

#### Scenario: 破损入破损状态
- **WHEN** 验货登记破损数量并过账
- **THEN** 该数量以 `damaged` 状态入暂存位，不进入可发池

#### Scenario: 别家货主商品混入被拒
- **WHEN** 收货扫描到不属于当前单据货主的商品
- **THEN** 该次扫描被拒绝，不产生库存变动

#### Scenario: 整批拒收零库存变化
- **WHEN** 仓管对整批货发起拒收并注明原因
- **THEN** 收货单与 ASN 转 `cancelled`，不产生任何库存与流水

#### Scenario: 收货过账按批次各记一条流水
- **WHEN** 确认收货过账，同一商品有多个批次且含破损
- **THEN** 每个批次的好货与破损各生成一条流水，货主由商品档案派生，幂等键含 `lot_id`

#### Scenario: 收货后账面存在但货在月台
- **WHEN** 收货过账完成、上架未完成
- **THEN** 库存账面已增加，货仍记在暂存位，账面位置为最后已知位置

#### Scenario: 选位按专属、就近、仓型优先级
- **WHEN** 生成上架任务
- **THEN** 依次尝试货主专属库位、同商品已有库位、按仓型规则选位，前一命中即止

#### Scenario: 温区不符放行并留痕
- **WHEN** 冷藏货在冷藏区无可用位而上了常温区
- **THEN** 仍允许上架，置 `temp_mismatch=true` 并提示，可在上架记录中筛出

#### Scenario: 同库位不同批次分两条库存
- **WHEN** 同一商品的两个批次上架到同一库位
- **THEN** 生成两条独立库存记录，账面按批次分开

#### Scenario: 跨库位移动记两条流水
- **WHEN** 上架确认一行
- **THEN** 同事务记一条暂存位扣减与一条目标位增加，批次跟随，`ref` 为 putaway

#### Scenario: 留样在上架完成时建立
- **WHEN** 留样行上架到留样库位
- **THEN** 生成留样记录，带批次、库位、到期日与 `holding` 状态，不在收货时建立

#### Scenario: 上架完成推进单据状态
- **WHEN** 全部上架行确认完成
- **THEN** putaway 转 `done`、receipt 转 `putaway_done`、ASN 转 `closed`

#### Scenario: 按批次核对账实
- **WHEN** 上架完成查看最终账面
- **THEN** 各批次账面数量之和等于该批次到货数量，破损不计入可发

#### Scenario: 留样区不参与出库分配
- **WHEN** 出库选货
- **THEN** 只从常规存储库位的可发数量里选，留样库位即使状态可发也不进入候选

#### Scenario: 破损转回可发或报废
- **WHEN** 仓管处置暂存位的破损货
- **THEN** 转回可发走同库位状态转换记账，报废走扣减流水，两者均可追溯

#### Scenario: 破损退回货主
- **WHEN** 货主同意把破损货退回
- **THEN** 建出库单从该库位出货，处置记录带可对账的 `ref_out_code`

#### Scenario: 撤单未到货的 ASN
- **WHEN** 货主取消未到货的 ASN
- **THEN** ASN 转 `cancelled`，不产生库存与流水

### Requirement: 库存台账验收场景

#### Scenario: 状态分别记账
- **WHEN** 同一货品同一库位既有可发又有冻结或破损

#### Scenario: 批次维度始终存在
- **WHEN** 未启用批次管理的商品产生库存
- **THEN** 落在默认批次上，数量与其他批次分开，后续启用批次时历史不迁移

#### Scenario: 不采集序列号
- **WHEN** 收发任何商品
- **THEN** 不要求录入单件序列号，同一批次内不区分单件身份

#### Scenario: 分配时可用量不足
- **WHEN** 出库需求超过该库位可发数量
- **THEN** 按可发数量分配或拒绝分配，不产生负库存

#### Scenario: 数量归零
- **WHEN** 某条库存的可发数量扣减至零
- **THEN** 记录保留并可查询历史，不做物理删除

#### Scenario: 冻结与解冻
- **WHEN** 把一部分可发数量转为冻结或转回可发
- **THEN** 该库位该货品总量不变，写一条带前后状态与来源单据的流水

#### Scenario: 状态转换可追溯

- **THEN** 能看出转出与转入状态、数量、来源单据与操作人

#### Scenario: 货主方用户查询库存
- **WHEN** 绑定货主 A 的用户查询库存
- **THEN** 只返回货主 A 的记录，总数与分页按该范围计算

#### Scenario: 直接访问他人记录
- **WHEN** 货主 A 的用户按标识访问货主 B 的库存或单据
- **THEN** 返回不存在或未授权，不泄露任何字段内容

#### Scenario: 仓库员工不受货主限制
- **WHEN** 未绑定货主身份的仓库员工查询
- **THEN** 可查看全部货主记录，并可按货主筛选

#### Scenario: 留样精确到批次

### Requirement: 库位策略验收场景
系统 SHALL 满足下列仓型坐标、温区、空间域、选位优先级与分配池场景（来源：`wms/location-policy`）。

#### Scenario: 平面仓
- **WHEN** 仓型为平面仓
- **THEN** 库位用区、巷道、位定位，不需要建筑楼层与货架层

#### Scenario: 楼层仓
- **WHEN** 仓型为楼层仓
- **THEN** 库位用建筑楼层、区、位定位，建筑楼层与货架层是独立字段

#### Scenario: 钢结构立库
- **WHEN** 仓型为立库

- **WHEN** 给定任意库位编码
- **THEN** 能解析出坐标各分量与所属空间域，标签编码与系统内编码一致

#### Scenario: 温区匹配优先
- **WHEN** 货品要求冷藏且冷藏区有空闲库位
- **THEN** 优先分配到冷藏区，常温区不作为第一候选

#### Scenario: 温区不匹配但允许上架
- **WHEN** 货品要求冷藏但冷藏区无可用库位
- **THEN** 仍可分配到其他温区，该次上架标记为温区不符并提示

- **WHEN** 查看上架记录
- **THEN** 能筛出所有被上架到非匹配温区的记录

- **WHEN** 两个库位所属空间域相同
- **THEN** 判定为同域作业，任务不标记跨域

#### Scenario: 跨域判定
- **WHEN** 两个库位所属空间域不同
- **THEN** 判定为跨域作业，任务上可看出从哪个域到哪个域

- **WHEN** 货主有可用专属库位

#### Scenario: 同商品就近合并
- **WHEN** 该商品已在某库位有库存且该库位可用
- **THEN** 优先分配到同一库位，已满或不可用时才继续下一条

- **WHEN** 平面仓且前两条未命中
- **THEN** 选距离收发货区最近的可用库位，高频周转商品优先靠近

#### Scenario: 楼层仓按楼层
- **WHEN** 楼层仓且前两条未命中
- **THEN** 收发货层有可用位就放本层，本层无位时按周转等级放低层

#### Scenario: 立库按巷道均衡
- **WHEN** 立库且前两条未命中
- **THEN** 选当前占用率最低的巷道，不让某巷道先被填满

#### Scenario: 暂存区不参与
- **WHEN** 上架或出库分配选位
- **THEN** 收货暂存区、发货暂存区、拣选区库位不进入候选

#### Scenario: 留样区不参与
- **WHEN** 出库分配选位
- **THEN** 留样库位不进入候选，即使其库存状态可发

#### Scenario: 换仓型不改流程
- **WHEN** 把仓型从平面仓改为楼层仓
- **THEN** 收货、上架、拣货、发运流程不变，只改变坐标含义与选位算法

#### Scenario: 不支持同时多种仓型
- **WHEN** 系统已配置为某一仓型
- **THEN** 不存在按仓型分别管理的第二套仓库

#### Scenario: 库位数量与规划值不符
- **WHEN** 实际启用库位数量少于规划总量
- **THEN** 系统正常运作，不因未达规划值告警

#### Scenario: 库位停用
- **WHEN** 某个库位被停用
- **THEN** 立即退出候选，其上已有库存不被自动移走，需人工处理

### Requirement: 出库验收场景

- **WHEN** 规则以截单时间为主要条件

- **WHEN** 规则包含热度分级

- **WHEN** 波次采用播种墙

#### Scenario: 分播数量校验
- **WHEN** 投放数量与格口要求不符
- **THEN** 提示并要求确认，差异记入分播异常

#### Scenario: 低于下限触发补货
- **WHEN** 拣选区某库位可发数量低于下限
- **THEN** 生成补货建议补至上限，补货量按整箱取整

#### Scenario: 补货执行
- **WHEN** 作业员执行补货
- **THEN** 从存储区扣减、拣选区增加在同一事务完成，批次跟随移动

#### Scenario: 拣选区缺货
- **WHEN** 拣选区库存不足且未及时补货
- **THEN** 分配跳过该库位，全仓不足时该订单行标记缺货，不静默少发

#### Scenario: 重量在容差内
- **WHEN** 实称重量与理论重量差值在容差内
- **THEN** 允许进入打面单环节

#### Scenario: 重量超差
- **WHEN** 差值超出容差
- **THEN** 拦截并标注重检，记录实称值、理论值与差值

#### Scenario: 商品缺重量数据
- **WHEN** 订单中有商品未维护单件重量
- **THEN** 该单不做称重比对，直接放行并记录告警

#### Scenario: 打印面单
- **WHEN** 包裹通过复核
- **THEN** 取电子面单数据下发到指定打印机，记录打印结果与重打次数

#### Scenario: 打印失败
- **WHEN** 打印机离线或缺纸
- **THEN** 明确提示失败原因，允许换机重打，不产生第二张有效面单

#### Scenario: 多打印机分工
- **WHEN** 仓库有多台打印机
- **THEN** 可按工位或单据类型绑定，打印任务落到绑定的那台

#### Scenario: 模板集中管理
- **WHEN** 需要调整面单或标签版式
- **THEN** 在后台修改模板并保存，所有工位下次打印即生效，无需重新部署前端或客户端

#### Scenario: 客户端不可用
- **WHEN** 本地打印客户端未启动或连接断开
- **THEN** 页面提示客户端离线并给出恢复指引，不静默失败、不把任务当作已打印

#### Scenario: 打印任务可回溯
- **WHEN** 查看某个包裹的打印记录
- **THEN** 能看到打印时间、目标打印机、成功与否、重打次数与操作人

#### Scenario: 吞吐不足时并行
- **WHEN** 单台客户端打印速度跟不上作业节奏
- **THEN** 可增配客户端按工位分担，每个工位只往自己的客户端下发

#### Scenario: 建单三入口共用服务
- **WHEN** 从后台、门户、开放接口任一入口建出库单
- **THEN** 共用同一建单服务，未建档商品拒单、货主单号重复拒单

#### Scenario: 出库状态机与取消
- **WHEN** 订单处于任一未分配状态
- **THEN** 可取消；已发运订单禁止取消，取消时 allocation 作废且库存数量不变

#### Scenario: FEFO 分配拆分
- **WHEN** 一个订单行跨多个批次满足
- **THEN** 按到期日拆成多条 allocation，数量之和等于订单行数量，留样区库存不被选中

#### Scenario: 分配失败整单回滚
- **WHEN** 订单任一行库存不足
- **THEN** 整单回滚，不留任何 allocation

#### Scenario: 拣货按库位路径排序
- **WHEN** 生成拣货单
- **THEN** 按巷道、架、层、位排序，同一库位的行相邻

#### Scenario: 拣货扫错库位被拒
- **WHEN** 拣货确认时扫到与行上不一致的库位编码
- **THEN** 拒绝并明确提示应扫与实扫的库位

#### Scenario: 复核可多次修改
- **WHEN** 同一单多次记录实称重量
- **THEN** 以最后一次为准

#### Scenario: 发运按批次扣减
- **WHEN** 执行发运
- **THEN** 锁订单、校验状态、每批次一条扣减流水、写发运记录，库存减少量等于订单行数量

#### Scenario: 重复发运幂等
- **WHEN** 对已发运订单再次发运
- **THEN** 直接返回原发运结果，不再扣减库存

#### Scenario: 分配量与实际库存不符
- **WHEN** 发运时发现分配量与实存不符
- **THEN** 拒绝发运并提示重新分配，库存数量不变

#### Scenario: 完整出库端到端
- **WHEN** 执行建单、分配、拣货、复核、发运全流程
- **THEN** 订单完成且库存减少与订单数量一致

#### Scenario: 开放接口跨货主查询
- **WHEN** 用某货主凭证查询另一货主的订单
- **THEN** 返回 404，不泄露订单是否存在

### Requirement: 计费验收场景
系统 SHALL 满足下列费用派生、幂等、红冲、仓储费、费率与账单场景（来源：`wms/billing`）。

#### Scenario: 未完成的单据不产生费用
- **WHEN** 单据处于进行中或已取消
- **THEN** 不生成费用；部分完成时按已完成数量计价

#### Scenario: 迟到的完成事实在下一轮补上
- **WHEN** 单据完成时间晚于上一轮计费扫描
- **THEN** 在下一轮扫描补生成费用，不因跨期漏账

#### Scenario: 计费不改变作业状态
- **WHEN** 计费域读取单据与库存数据
- **THEN** 只读不回写作业表，计费失败不影响作业继续

#### Scenario: 同一单据被多轮扫描到
- **WHEN** 同一张已完成单据出现在两轮扫描结果
- **THEN** 费用只有一条，第二轮跳过而非覆盖金额

#### Scenario: 并发扫描
- **WHEN** 两轮扫描同时处理同一来源
- **THEN** 只有一条写入成功，另一轮按已存在处理

#### Scenario: 费率用错
- **WHEN** 已生成的费用被判定为费率错误
- **THEN** 追加一条负数费用冲抵，原记录保持原样可查

#### Scenario: 修改已有费用的请求被拒绝
- **WHEN** 任何入口尝试改写或删除已生成费用
- **THEN** 请求被拒绝

#### Scenario: 当日占用换算仓储费
- **WHEN** 某货主某日占用若干库位
- **THEN** 按占用数乘该货主日单价计费，同一货主同一天只结算一次

#### Scenario: 不同存储类型分别计价
- **WHEN** 货主同时占用常规库位与留样库位
- **THEN** 两类占用按各自日单价分别生成费用，账单分行列示

#### Scenario: 未配置存储类型的专属费率
- **WHEN** 货主只配置通用仓储费率而无留样区专属费率
- **THEN** 留样区按通用费率计算，补专属费率后从生效日起分别计价

#### Scenario: 快照缺失时不出账
- **WHEN** 出账时发现某日快照缺失
- **THEN** 该账期账单不生成，提示先补齐快照，不按实时库存推算

#### Scenario: 月中调价
- **WHEN** 货主费率在账期中途调整
- **THEN** 调整前后天数分别按旧新费率，已生成费用不重算

#### Scenario: 货主无专属费率
- **WHEN** 货主未配置某计费项费率
- **THEN** 取全局默认费率；全局也未配置则该项不产生费用并记录告警

#### Scenario: 同一货主同一账期只有一张账单
- **WHEN** 重复生成同一货主同一账期的账单
- **THEN** 复用已有账单，不产生第二张

#### Scenario: 已确认账单的调整
- **WHEN** 账单已确认后需要调整金额
- **THEN** 在下一账期追加冲抵项，不修改已确认账单明细

#### Scenario: 账单金额可逐笔回溯
- **WHEN** 查看账单中的任一计费项
- **THEN** 可追溯到来源单据或快照，以及当时适用的费率

### Requirement: 移动作业端验收场景
系统 SHALL 满足下列作业端形态、信任边界、版本门槛与网络约束场景（来源：`wms/mobile-app`，含 `add-mobile-web` 浏览器形态增量）。

#### Scenario: 功能变更同步生效
- **WHEN** Web 端某个页面或校验规则调整
- **THEN** 作业端下次发版后表现一致，不存在需两处分别修改的实现

#### Scenario: 接口与鉴权一致
- **WHEN** 作业端调用后端
- **THEN** 使用与 Web 端相同的接口与鉴权，不因来自移动端放宽校验

#### Scenario: 打开作业端
- **WHEN** 作业员打开应用
- **THEN** 只进入移动作业路由组，无法进入货主自助端或后台管理界面

#### Scenario: 直接访问其他路由组
- **WHEN** 在作业端应用内访问货主端或后台路由
- **THEN** 被拒绝，不因客户端类型相同而放行

#### Scenario: 同一账号两端能力一致
- **WHEN** 同一账号分别在 Web 端与作业端操作
- **THEN** 可见数据与可执行动作完全相同

#### Scenario: 伪造客户端标识
- **WHEN** 请求伪造移动端标识
- **THEN** 权限判定结果不变，不出现仅凭客户端标识放行的路径

#### Scenario: 系统版本过低
- **WHEN** 设备 Android 版本低于 14 且尝试安装或启动应用
- **THEN** 给出明确提示，不进入必然出错的界面

#### Scenario: 应用内资源与服务端不兼容
- **WHEN** 已加载的前端资源与服务端接口不再匹配
- **THEN** 提示升级或刷新，不静默失败或抛出堆栈

#### Scenario: 断网提交
- **WHEN** 无网络时提交作业
- **THEN** 操作失败并给出重试提示，不在本地暂存后自动补传

#### Scenario: 弱网下重复提交
- **WHEN** 网络抖动导致同一操作被提交两次
- **THEN** 由幂等规则收敛为一次，不产生重复任务完成或重复扣减

#### Scenario: 货主提出移动端需求
- **WHEN** 货主要求在手机上使用自助端
- **THEN** 不提供安装包，门户页面不为手机屏幕单独适配

#### Scenario: 验收范围
- **WHEN** 验收货主自助端
- **THEN** 以桌面浏览器表现为准，窄屏可用性不作为验收项

#### Scenario: 浏览器打开作业端
- **WHEN** 用作业员账号在浏览器访问作业端地址
- **THEN** 进入移动作业路由组，页面按窄屏宽度布局并可在桌面浏览器居中显示

#### Scenario: 浏览器形态没有安装包
- **WHEN** 某台设备需要作业端
- **THEN** 可不装任何东西用浏览器直接使用，功能与 APK 形态一致

#### Scenario: 扫码在两种形态下都能用
- **WHEN** 设备不能提供扫码广播
- **THEN** 退化为键盘模拟输入，两种形态共用同一条降级路径

#### Scenario: 打印不因形态降级
- **WHEN** 浏览器形态需要打面单或标签
- **THEN** 同样通过本地打印代理下发，不退化成只支持 A4 打印

#### Scenario: 浏览器版本过低
- **WHEN** 浏览器版本低于支持范围
- **THEN** 打开页面时明确提示所需版本，不呈现布局错乱或按钮点不动的界面

### Requirement: 集成与上游同步验收场景
系统 SHALL 满足下列数据主从、编码匹配、订单推进、库存回传与断线作业场景（来源：`wms/upstream-sync`，`integrate-warehouse-network`）。

#### Scenario: 本地试图修改上游字段
- **WHEN** 任何入口尝试修改由上游维护的字段
- **THEN** 请求被拒绝并提示该字段由上游维护，不出现改了又被同步覆盖的静默回退

#### Scenario: 上游试图覆盖本地存储属性
- **WHEN** 上游同步一条已存在的商品
- **THEN** 事实层字段被更新，优先库区、一托件数、上架要求保持本地值

#### Scenario: 上游同步的字段本地只读
- **WHEN** 查看来自上游同步的商品字段
- **THEN** 这些字段在本地为只读，不接受本地写入

#### Scenario: 上游下发一个未登记的商品
- **WHEN** 收到的商品在本地找不到同货主同编码记录
- **THEN** 新建商品并自动生成仓库编码，返回该编码给上游

#### Scenario: 上游下发一个已登记的商品
- **WHEN** 按货主与货主编码能找到本地记录
- **THEN** 更新事实层字段，保持仓库编码不变

#### Scenario: 两个货主用了同一个商品编码
- **WHEN** 货主 A 与货主 B 都下发编码 `A001`
- **THEN** 分别建两条商品记录、各自生成不同仓库编码，不因编码相同而合并

#### Scenario: 仓库修改自己的编码
- **WHEN** 仓库调整某商品的仓库编码
- **THEN** 允许修改但校验全仓唯一，货主编码不受影响

#### Scenario: 本地修改订单内容
- **WHEN** 尝试修改上游订单的商品、数量或收件信息
- **THEN** 请求被拒绝并提示需由上游取消后重新下发

#### Scenario: 订单取消
- **WHEN** 上游取消一张未发货的订单
- **THEN** 订单转取消并释放已分配库存，已发货订单不允许取消

#### Scenario: 过账后实时推送
- **WHEN** 任何一次库存变动被提交
- **THEN** 在合理延迟内推送一条带幂等标识的变更事件，重复推送不重复扣减

#### Scenario: 定时全量快照
- **WHEN** 到达快照时间
- **THEN** 推送当前全部可发库存，供上游校准与事件的偏差

#### Scenario: 推送失败
- **WHEN** 推送因网络或上游故障失败
- **THEN** 记录待重推并指数退避，不因推送失败回滚本地已提交的库存变动

#### Scenario: 上游断线收货
- **WHEN** 上游不可用时有货到达
- **THEN** 仍可完成收货与上架，结果积压在待推队列，恢复后补推

#### Scenario: 上游断线时的订单
- **WHEN** 上游不可用
- **THEN** 已下发订单继续执行，无法获取新订单时页面明确提示同步中断

#### Scenario: 恢复后补推
- **WHEN** 上游恢复
- **THEN** 按时间顺序补推积压变更与结果，全量快照作最终校准

#### Scenario: 查看同步记录
- **WHEN** 打开同步日志
- **THEN** 能按方向、对象类型、状态筛选，失败记录可手工重推

#### Scenario: 数据对不上时定位
- **WHEN** 上游与本地对同一商品数量不一致
- **THEN** 能查到最近一次同步的时间与内容，可用全量快照覆盖差异
