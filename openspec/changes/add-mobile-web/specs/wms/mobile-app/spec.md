# Spec Delta

## ADDED Requirements

### Requirement: 作业端提供浏览器形态

系统 SHALL 让作业端既可作为 Android 应用运行，也可直接在浏览器打开使用，两者共用同一份前端构建与同一套接口。

APK 是主力形态（扫码枪、蓝牙打印、离线以外的稳定体验），浏览器形态是补位——PDA 不够用时、新员工上手、管理者在电脑上代操作、或扫码枪出故障需要键盘输入时，打开浏览器就能干活。

#### Scenario: 浏览器打开作业端

- **WHEN** 用作业员账号在浏览器访问作业端地址
- **THEN** 进入移动作业路由组
- **AND** 页面按窄屏宽度布局，可在桌面浏览器上居中显示

#### Scenario: 浏览器形态没有安装包

- **WHEN** 某台设备需要作业端
- **THEN** 可以不装任何东西，用浏览器直接使用
- **AND** 功能与 APK 形态一致，不因为浏览器而减少能力

#### Scenario: 扫码在两种形态下都能用

- **WHEN** 设备能提供扫码广播
- **THEN** 使用广播结果
- **AND** 否则退化为键盘模拟输入，两种形态共用同一条降级路径

#### Scenario: 打印不因形态降级

- **WHEN** 浏览器形态需要打面单或标签
- **THEN** 同样通过本地打印代理下发
- **AND** 不退化成只支持 A4 打印

## MODIFIED Requirements

### Requirement: 系统版本与资源版本都有明确门槛

系统 SHALL 按形态分别校验版本：Android 应用校验系统版本，浏览器形态校验浏览器版本；两种形态都要在应用内资源与服务端接口不兼容时提示升级。

#### Scenario: 系统版本过低

- **WHEN** 设备 Android 版本低于 14 且尝试安装或启动应用
- **THEN** 给出明确提示
- **AND** 不进入一个必然出错的界面

#### Scenario: 浏览器版本过低

- **WHEN** 浏览器版本低于支持范围
- **THEN** 打开页面时给出明确提示，说明需要什么版本
- **AND** 不呈现一个布局错乱或按钮点不动的界面

#### Scenario: 应用内资源与服务端不兼容

- **WHEN** 已加载的前端资源与服务端接口不再匹配
- **THEN** 提示升级或刷新
- **AND** 不静默失败或抛出堆栈
