# Proposal

## Why

已归档的 `wms/mobile-app` 规格只写了 Android 作业端，把 `/m/*` 路由组等同于"装在 PDA 上的应用"。实际上作业端必须在浏览器里也能用——PDA 数量有限、新员工上手、管理者在自己电脑上代操作、扫码枪出故障时改用键盘输入，这些场景都要求打开浏览器就能干活。

不改这条的话，P5 会按"只有 APK"去实现，事后补 Web 形态要动扫码桥接与版本门槛两处。

## What Changes

- 作业端明确为**两种形态**：Android 应用（PDA 主力）与浏览器页面（桌面或手机浏览器均可用），共用同一份前端构建与同一套接口。
- 版本门槛分开：APK 卡 Android 系统版本，浏览器形态卡浏览器版本。
- 扫码统一走"能拿到广播就用广播，拿不到就用键盘模拟"，两种形态共用同一条降级路径，不做两套输入逻辑。
- 打印在两种形态下都通过本地打印代理，不因为浏览器就降级成 A4。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `wms/mobile-app`: 新增「作业端提供浏览器形态」一条；修改「系统版本与资源版本都有明确门槛」，把 Android 系统版本的门槛限定在 APK 形态，浏览器形态改按浏览器版本判定。

## Impact

- `docs/design/ui-map.md` 的作业端路由说明要补一句"浏览器可直接访问"。
- `docs/design/tech-stack.md` 的移动端章节要写明两形态共用一个 `dist`。
- P5 的验收要加一条：不装 APK，用浏览器打开 `/m/tasks` 能完成一次扫码作业。
- 不影响 P0–P4，也不影响任何后端接口。
