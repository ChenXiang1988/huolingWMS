# Spec Delta

## Purpose

让任务既能按规则派给指定作业员与 PDA，也能留在公共池由作业员抢领；货量过大时把一道工序拆成多条子任务并行执行并汇总回父任务。本能力只改任务的分配与结构，不改业务域状态机。

## ADDED Requirements

### Requirement: 任务有两种分配方式
系统 SHALL 让每条任务标明分配方式，系统派单与公共池抢单并存，同一时刻一条任务只有一种归属。

#### Scenario: 系统派单到指定人
- **WHEN** 一条任务配置为派单并指定了作业员
- **THEN** 任务直接落到该作业员的待办，其 PDA 可见
- **AND** 其他作业员的 PDA 看不到该任务

#### Scenario: 派单到指定 PDA
- **WHEN** 一条任务按工位或设备绑定到某台 PDA
- **THEN** 该 PDA 登录后可见此任务
- **AND** 同一账号换另一台 PDA 登录时行为按绑定规则处理

#### Scenario: 公共池抢单
- **WHEN** 一条任务配置为抢单并进入公共池
- **THEN** 任意有权限的作业员可领取，先到先得
- **AND** 领取后其他人不可再领

#### Scenario: 派单失败转公共池
- **WHEN** 系统按规则派单但目标作业员不可用
- **THEN** 任务转入公共池并标记转池原因
- **AND** 不因为派单失败而卡住工序进度

#### Scenario: 两种方式的分配记录可区分
- **WHEN** 查看一条任务
- **THEN** 能看到它是派单还是抢单、指派人、实际领取人
- **AND** 指派人与领取人不同时可看出差异

### Requirement: 派单与领取并发只落一人
系统 SHALL 用行锁保证同一任务在派单、领取、改派之间只有一个成功者。

#### Scenario: 两人同时抢同一任务
- **WHEN** 两个作业员同时领取同一条公共池任务
- **THEN** 只有一人成功，另一人收到任务已被领取的提示
- **AND** 不产生两条领取成功记录

#### Scenario: 派单与抢单同时发生
- **WHEN** 系统派单与作业员抢单同时命中同一任务
- **THEN** 只有一个操作成功，另一个按当前任务状态被拒绝或改为幂等返回
- **AND** 任务最终只有一个归属

#### Scenario: 重复派单幂等
- **WHEN** 对已派给同一人的任务再次派单
- **THEN** 保持原指派不变，不生成重复待办

### Requirement: 超时按分配方式分别处理
系统 SHALL 让派单任务与抢单任务在超时后走不同路径，不再一律回归公共池。

#### Scenario: 抢单任务超时回归
- **WHEN** 抢单任务领取后超过时限未提交
- **THEN** 状态回归待领，领取人清空
- **AND** 维持现有行为，不自动改派

#### Scenario: 派单任务超时改派
- **WHEN** 派单任务超过时限未提交且配置为改派
- **THEN** 按规则重新指派给其他可用作业员
- **AND** 记录改派前后指派人与改派原因

#### Scenario: 派单任务超时转池
- **WHEN** 派单任务超时且配置为转公共池或无可用改派对象
- **THEN** 任务转入公共池等待抢领
- **AND** 保留原指派历史供追溯

#### Scenario: 改派不丢执行记录
- **WHEN** 任务被改派给另一人
- **THEN** 原作业员已做的扫码或执行记录保留
- **AND** 新作业员接手后能看到此前进度

### Requirement: 任务可按数量或商品拆子任务
系统 SHALL 支持把一条父任务拆成多条子任务并行执行，子任务完成汇总回父任务。

#### Scenario: 按数量拆任务
- **WHEN** 一道工序的货量超过单批处理上限
- **THEN** 按数量拆成多条子任务，各带拆分序号与数量
- **AND** 各子任务数量之和等于父任务数量

#### Scenario: 按商品拆任务
- **WHEN** 一条任务含多个商品且需要并行处理
- **THEN** 按商品拆成多条子任务
- **AND** 子任务的货主与父任务一致

#### Scenario: 子任务可分别派工
- **WHEN** 多条子任务生成后
- **THEN** 每条子任务可独立派给不同作业员或 PDA
- **AND** 子任务的分配方式可与父任务不同

#### Scenario: 子任务全部完成才完成父任务
- **WHEN** 存在未完成或失败的子任务
- **THEN** 父任务保持进行中并标出未完成子任务
- **AND** 失败子任务的数量不计入已完成汇总

#### Scenario: 作废父任务连带子任务
- **WHEN** 一条未完成父任务被作废
- **THEN** 其下未完成子任务一并作废
- **AND** 已完成子任务保留历史

#### Scenario: 重复拆分幂等
- **WHEN** 同一父任务被重复触发生成子任务
- **THEN** 已有未完成任务时不重复生成
- **AND** 复用现有来源去重规则

### Requirement: 派单按可配置规则选择目标
系统 SHALL 按配置的规则选择派单目标，规则可组合，不写死单一算法。

#### Scenario: 按作业区派单
- **WHEN** 规则包含作业区条件
- **THEN** 任务派给该作业区内的作业员
- **AND** 作业区外的作业员看不到该派单任务

#### Scenario: 按在手任务量均衡
- **WHEN** 规则包含在手任务量条件
- **THEN** 优先派给在手任务较少的作业员
- **AND** 不把任务全部堆给同一人

#### Scenario: 多规则并存
- **WHEN** 同时启用多条派单规则
- **THEN** 按优先级依次匹配，先命中的规则生效
- **AND** 无规则命中的任务进入公共池

#### Scenario: 技能或工位不匹配被排除
- **WHEN** 某作业员不具备任务要求的技能或不在绑定工位
- **THEN** 该作业员不作为派单目标
- **AND** 不因排除后无人可用而静默派给不匹配对象
