## 3. 入库预报与服务订单

- [x] 3.2 ASN 明细校验：引用未建档商品编码时拒绝建单；验证标准：返回明确提示而不是 500

- [x] 3.3 服务订单接口：随 ASN 提交留样要求（固定数量或比例、留样天数、到期处置方式）；验证标准：`sku_id` 为空时对全部商品生效

## 4. 收货

- [x] 4.1 开收货单：按 ASN 生成 `receipt` 与明细，复制应收数量；验证标准：一个 ASN 可开多张，ASN 状态保持 `receiving`
      —— 应收数量按"预报数量 − 该 ASN 此前已收"计算，分批到货时第二张单只带剩余量；已收满时明确拒绝
- [x] 4.2 录入实收：按批次拆分（`receipt_lot`），记录破损；验证标准：各批次之和等于该行实收
      —— 批次合计不等时 422「各批次合计 90 与实收 100 不一致」
- [x] 4.3 超收拒绝：实收大于应收时拒绝；验证标准：返回 422 并提示需货主追加预报
- [x] 4.4 收货确认过账：好货入 `available`、破损入 `damaged`，同事务写流水；验证标准：重复确认不重复过账
      —— 实测 available 97（两批次）+ damaged 3；重复确认返回 422「状态 checked 不能确认」
- [x] 4.5 未建档条码拒扫：扫码校验接口；验证标准：不存在的条码返回明确错误
      —— 2026-11-22 补：`GET /wms-inbound/receipts/{id}/scan?code=` 按收货单归属的货主
      解析 `wms_master_data_barcode`，归属从收货单取、不收请求体 `owner_id`；收货抽屉加扫码框，
      命中定位并高亮明细行，未建档 422。实测见文末实施记录

## 5. 上架

- [x] 5.1 生成上架任务：按选位优先级算目标库位，温区优先匹配；验证标准：冷藏货优先落冷藏区
      —— P2 只做到"温区优先 + 存储区兜底"，专属库位与同商品就近合并留给 P4 的选位策略
- [x] 5.2 温区不匹配：无匹配库位时放行并置 `temp_mismatch`；验证标准：记录可回查
- [x] 5.3 上架确认：扫库位完成一行，扣暂存加目标；验证标准：库存位置随之前移
      —— 实测三行上架后货从暂存位 21 移到存储位 1（92）与留样位 22（5）
- [x] 5.4 留样行：上架完成时生成 `sample` 记录并带批次；验证标准：记录里的库位就是实际库位
      —— P5 建 `wms_internal_ops_sample` 后由 `backfill_samples()` 从
      `wms_inbound_putaway_line.sample_flag` 历史行回填，库位取实际库位；台账页可逐条处置
