# Proposal

## Why

货主门户当前把输入和列表堆在同一屏：商品档案页表单在上、列表在下；出库订单页列表在上、表单在下，表单常驻，用户分不清自己是在"查看"还是"录入"。入库预报页更极端——只有输入表单，没有提交记录，提交后只弹一句成功提示，用户不知道单据去哪看。这种交互让用户迷茫，也容易重复提交或误操作。

后台已有成熟范式：列表页点「新建」弹右侧抽屉，提交后关抽屉刷新列表。但全项目 20 处 `el-drawer` 都是各页手写，没有统一骨架；用户此前定过 PC 端右侧抽屉的标准外观（头部标题/副标题/状态标签/关闭、左侧分段目录 + 右侧两列字段、底部右对齐操作）。这次先把这套骨架做成共享组件，再改造门户页面。

## What Changes

- 新建共享抽屉组件，按已定的标准外观实现：头部标题/副标题/状态标签/关闭，主体左侧分段目录 + 右侧两列字段，底部操作右对齐。支持"新建"和"详情"两种模式。
- 商品档案页：列表页只保留表格和「新建」按钮；建档表单移入右侧抽屉，提交后关抽屉、刷新列表。
- 出库订单页：列表页只保留列表与筛选；建单表单移入右侧抽屉；已有详情抽屉改用共享组件。
- 入库预报页：保留输入表单入口，但增加"我的预报"提交记录列表（单号、货主单号、状态、到货时间、提交时间），点记录可看详情；输入也改为右侧抽屉。
- 后端新增货主门户的入库预报列表与详情接口，按会话 `owner_id` 过滤，不暴露其他货主单据。
- 所有抽屉统一提供明确的"保存/取消"与提交后反馈，避免用户不确定是否成功。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `wms/owner-access`: 明确自助端的录入交互——列表与输入分离、通过右侧抽屉承载录入、提交后能看到结果与状态；明确货主可查看自己提交的入库预报。
- `wms/admin-navigation`: 补充两端共用的抽屉外观标准作为导航/交互约束（PC 端右侧抽屉统一骨架）。

## Impact

- 前端：新增 `frontend/src/components/OwnerFormDrawer.vue`（或通用名 `AppFormDrawer.vue`）；改 `views/wms_master_data/portal/{sku,order,asn}/index.vue`；`router/owner.ts` 不变（仍用页内抽屉，不新增路由）。
- 后端：`wms_inbound/api.py` 新增 `/wms-inbound/portal/asns` GET 列表与 `/{id}` 详情；复用创建接口的服务层与 `owner_of_user`。
- 数据：无表结构变更。
- 兼容性：货主看到的菜单、路由、权限不变；只是页面内交互方式变化。
