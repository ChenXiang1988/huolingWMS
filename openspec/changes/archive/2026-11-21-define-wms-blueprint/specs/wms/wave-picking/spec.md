# Spec Delta

## Purpose

日单量三万级、B 端与 C 端混合作业。这个能力定的是订单怎么组成波次、拣完怎么分到每张单、拆零的货从哪来、错了怎么拦住。库存"账"在 `stock-ledger`，批次在 `lot-control`，这里管的是"三万张单怎么在一天里发出去"。

## ADDED Requirements

### Requirement: 出库按订单类型走两条分支

系统 SHALL 按订单类型区分整箱出库与拆零出库，两者共用同一套单据与库存记账，仅在分配与拣货方式上不同。

#### Scenario: B 端整箱出库

- **WHEN** 订单类型为 B 端
- **THEN** 分配优先选整箱、整托的库位
- **AND** 拣货以箱为最小单位，不做拆零

#### Scenario: C 端拆零出库

- **WHEN** 订单类型为 C 端
- **THEN** 分配优先从拆零拣选区取货
- **AND** 拣货以件为最小单位

#### Scenario: 同一波次不混类型

- **WHEN** 生成波次
- **THEN** 一个波次只包含一种订单类型
- **AND** 两类订单各自成波，避免整箱与拆零混在一次拣货里

### Requirement: 波次按可组合规则分组

系统 SHALL 用可配置的规则把订单池切成波次，规则条件可组合，不是固定算法。

条件的候选维度：订单类型、承运商、收货区域、截单时间窗口、商品热度分级。规则可只取其中几项，也可全部取用。

#### Scenario: 按截单时间分批

- **WHEN** 规则以截单时间为主要条件
- **THEN** 同一截单窗口内的订单归入同一波次
- **AND** 超过窗口的订单留到下一波

#### Scenario: 按承运商与区域分组

- **WHEN** 规则包含承运商与区域
- **THEN** 同一波次内订单的承运商与区域一致
- **AND** 便于按承运商分别交运、按区域优化路线

#### Scenario: 按热度分级

- **WHEN** 规则包含热度分级
- **THEN** 爆款订单单独成波，冷门订单合并成波
- **AND** 避免爆款与冷门混拣拉长行走距离

#### Scenario: 多条规则并存

- **WHEN** 同时启用多条规则
- **THEN** 按优先级依次匹配，先命中的先成波
- **AND** 未被任何规则命中的订单留在池中等待下一轮

### Requirement: 波次生成异步执行

系统 SHALL 把波次生成放在后台执行，请求只负责提交与查询进度。

#### Scenario: 提交生成

- **WHEN** 操作者提交波次生成
- **THEN** 立即返回任务标识
- **AND** 不阻塞等待结果

#### Scenario: 生成过程中可查进度

- **WHEN** 后台正在分配订单
- **THEN** 可查询已处理单数与当前阶段
- **AND** 长时间无进展时可中止

#### Scenario: 生成失败可重试

- **WHEN** 生成中断
- **THEN** 已生成的分配回滚，订单退回订单池
- **AND** 允许重新生成，不产生重复分配

### Requirement: 分播支持播种墙与边拣边分

系统 SHALL 支持两种分播方式，由波次创建时选定，同一时刻同一波次只用一种。

#### Scenario: 播种墙分播

- **WHEN** 波次采用播种墙
- **THEN** 拣货按库位聚合，一次取出多个订单所需的总量
- **AND** 分播时按格口提示每个订单放几件
- **AND** 格口与订单一一对应

#### Scenario: 边拣边分

- **WHEN** 波次采用边拣边分
- **THEN** 拣货车直接对应一张订单
- **AND** 拣货与分播是同一个动作，不设独立分播环节

#### Scenario: 分播数量校验

- **WHEN** 投放数量与格口要求不符
- **THEN** 提示并要求确认
- **AND** 差异记入分播异常

### Requirement: 拆零依赖补货

系统 SHALL 从存储区向拣选区补货，补货按库位的上下限触发，拆零拣选只能消耗拣选区库存。

#### Scenario: 低于下限触发补货

- **WHEN** 拣选区某库位的可发数量低于配置的下限
- **THEN** 生成补货建议，补至上限
- **AND** 补货量按整箱取整，不拆箱补货

#### Scenario: 补货执行

- **WHEN** 作业员执行补货
- **THEN** 从存储区库位扣减、拣选区库位增加，同一事务完成
- **AND** 批次跟随移动

#### Scenario: 拣选区缺货

- **WHEN** 拣选区库存不足且未及时补货
- **THEN** 分配时跳过该库位
- **AND** 若全仓不足则该订单行标记缺货，不静默少发

### Requirement: 打包后称重拦截

系统 SHALL 在打包环节称重并与订单理论重量比对，超差拦截不放行。

理论重量 = 各订单行数量 × 商品单件重量 + 包装耗材基准重量。

#### Scenario: 重量在容差内

- **WHEN** 实称重量与理论重量差值在容差内
- **THEN** 允许进入打面单环节

#### Scenario: 重量超差

- **WHEN** 差值超出容差
- **THEN** 拦截并标注重检
- **AND** 记录实称值、理论值与差值

#### Scenario: 商品缺重量数据

- **WHEN** 订单中有商品未维护单件重量
- **THEN** 该单不做称重比对，直接放行并记录告警
- **AND** 不因为缺数据而阻断发货

### Requirement: 面单与标签由本地代理打印

系统 SHALL 通过局域网打印代理向热敏打印机下发面单与标签，浏览器只负责触发。

#### Scenario: 打印面单

- **WHEN** 包裹通过复核
- **THEN** 系统取电子面单数据并下发到指定打印机
- **AND** 记录打印结果与重打次数

#### Scenario: 打印失败

- **WHEN** 打印机离线或缺纸
- **THEN** 明确提示失败原因
- **AND** 允许换机重打，不产生第二张有效面单

#### Scenario: 多打印机分工

- **WHEN** 仓库有多台打印机
- **THEN** 可按工位或单据类型绑定打印机
- **AND** 打印任务落到绑定的那台
