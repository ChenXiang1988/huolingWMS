# Proposal

## Why

P0 只立起了骨架：两个空插件、一套菜单、一个落点判定。仓库里还不能录一个货主、一个商品、一条库位，也没有库存表。

P1 要做的就是把地基浇筑成实体——主数据能录、库存能记。之后每一期（入库、出库、波次、计费）都踩在这两块上，它们的表结构与记账契约一旦定错，后面全部返工。

## What Changes

- **主数据域**：仓库配置（仓型）、货主与账号绑定、库区与库位（坐标、类型、温区、拆零上下限）、商品（两套编码、字段分组、批次开关、箱规、温区要求）、条码、合作方、API 凭证、单号序列。
- **库存域**：库存台账、库存流水、批次，以及两个唯一的写入口 `post_stock` 与 `transfer_status`。
- **幂等与并发**：库存流水的唯一键、行锁、负库存拦截，三条一起保证"重复提交不多记、并发过账不双扣"。
- **菜单与权限**：主数据域六个页面、库存域三个页面的菜单与按钮级权限落库，角色按 `interface-map.md` 绑定。
- **前端占位页转正**：把 P0 的两个占位页换成可用的列表与表单页面。

## Capabilities

本变更不新增也不修改行为规格——`wms/domain-map`、`wms/stock-ledger`、`wms/lot-control` 已经把该做的东西写清楚了，P1 只是把它们落到代码里。

### New Capabilities

无。

### Modified Capabilities

无。

## Impact

- 新增 11 张主数据表、4 张库存表；全部走插件的 `install()` 建表，不碰基座迁移。
- 新增两个业务域的实际路由与前端页面，插件从骨架变为可用。
- P2 的入库会直接调用 `post_stock`，所以本期的记账契约形状必须与 `docs/design/interface-map.md` 逐参数一致。
- 不新增任何第三方依赖。
