# Spec Delta

## MODIFIED Requirements

### Requirement: 面单与标签由本地代理打印

系统 SHALL 通过本地打印客户端向打印机下发面单与标签，打印模板集中管理、打印结果留痕，浏览器只负责触发。

前端用 `vue-plugin-hiprint` 渲染模板并经 socket.io 下发到 `electron-hiprint` 客户端，由客户端调用操作系统打印驱动出纸。模板是 JSON，存在后台，改版式不需要发布前端。

#### Scenario: 打印面单

- **WHEN** 包裹通过复核
- **THEN** 系统取电子面单数据并下发到指定打印机
- **AND** 记录打印结果与重打次数

#### Scenario: 打印失败

- **WHEN** 打印机离线或缺纸
- **THEN** 明确提示失败原因
- **AND** 允许换机重打，不产生第二张有效面单

#### Scenario: 多打印机分工

- **WHEN** 仓库有多台打印机
- **THEN** 可按工位或单据类型绑定打印机
- **AND** 打印任务落到绑定的那台

#### Scenario: 模板集中管理

- **WHEN** 需要调整面单或标签的版式
- **THEN** 在后台修改模板并保存
- **AND** 所有工位下一次打印即生效，不需要重新部署前端或客户端

#### Scenario: 客户端不可用

- **WHEN** 本地打印客户端未启动或连接断开
- **THEN** 页面明确提示客户端离线，并给出恢复指引
- **AND** 不静默失败，也不把任务当作已打印

#### Scenario: 打印任务可回溯

- **WHEN** 查看某个包裹的打印记录
- **THEN** 能看到打印时间、目标打印机、成功与否、重打次数与操作人
- **AND** 失败时能看到原因

#### Scenario: 吞吐不足时并行

- **WHEN** 单台客户端的打印速度跟不上作业节奏
- **THEN** 可增配客户端，按打包工位分担
- **AND** 每个工位只往自己的客户端下发，不跨机排队
