# Proposal

## Why

P2 让货进得来，P3 让货出得去。这是全系统工作量最大的一期：订单、分配、拣货、复核、发运五个状态机串在一起，任何一环的幂等没做对，后面每一笔出库都是错账。

三万单/天 ≈ 1.7 单/秒、单订单 2–5 行。这个量级决定了分配按订单为单位做（不引入分布式预占），真正的热点在拣货与波次，所以波次留到 P4。

## What Changes

- **出库订单**：货主经 API 或门户建单，含 B/C 两种类型、承运商、收件信息；未建档商品拒单，重复单号拒单。
- **FEFO 分配**：一次订单所有行用一条 `IN` 查询取回候选库存，内存按到期日排序；只从 `storage`/`picking` 取货，显式排除留样区；指定批次不足整行失败，不自动换批。
- **拣货**：按分配结果生成拣货单与行，按库位路径排序；扫码确认，扫错库位就地拒绝。
- **复核与称重**：理论重量 = 行数量 × 单件重量；实际偏差超阈值（默认 5%）拦下并要求复核。
- **发运**：扣减库存（每批次一条流水）、写发运记录；重复发运只扣一次。
- **破损处置第三路径**：`return_owner` 在 P3 开放，走"建出库单出货"。
- **开放接口**：货主可经 `X-API-Key` 推送出库订单。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。`wms/wave-picking`、`wms/stock-ledger`、`wms/owner-access` 已经把这一期的行为写清楚了。

## Impact

- 新建 `wms_outbound` 插件包，8 张表：`order`、`order_line`、`allocation`、`pick`、`pick_line`、`check`、`shipment`（+ 波次的表留 P4）。
- 前端 5 个页面：出库订单、拣货、复核与发运（波次看板 P4 补）。
- 门户新增「出库订单」页，货主可自助建单。
- 库存域新增一个只读契约：按 `(owner, sku)` 批量查可用库存（分配用，不写数量）。
- 不新增依赖。
