# Proposal

## Why

huolingWMS 是仓网里的一座仓，独立部署、自己的库，但业务上受 ERP 与仓网调度：货主与商品从上游来，订单从 ERP 的履约决策来，库存要回传。

蓝图是按"独立系统、货主直接对仓下单"设计的。接到仓网之后，这条主线要改成"上游为主、本仓执行为辅"，否则会出现两个主体对同一份数据各自维护、谁也说不清谁对。

## What Changes

- **明确两套商品编码并存**：仓库 SKU 编码（本仓唯一，库内作业用）与货主商品编码（同货主内唯一，对接用）。两者不冲突、不互相覆盖，按货主编码做同步的匹配键。
- **商品档案按来源分权**：上游同步来的事实层字段本地只读；仓库自己补的存储属性上游不覆盖。
- **门户建单按货主开关**：接了 ERP 的货主，门户降为查询端；没接的仍可用门户与 API 建单。
- **新增同步契约**：货主、商品、订单下行；库存快照与作业结果上行。明确主从方向与幂等键。
- **库存双通道回传**：过账后实时推变更，另每 5 分钟推一次全量快照。

## Capabilities

### New Capabilities

- `wms/upstream-sync`: 与 ERP、仓网之间的同步契约——谁主谁从、匹配键、幂等、库存双通道回传、断线补推

### Modified Capabilities

- `wms/domain-map`: 修改「主数据按谁的实物知识分工写入」，从"货主建 + 仓库补"扩为三种来源（上游同步 / 货主自建 / 仓库补充），并新增两套编码并存的约束
- `wms/owner-access`: 修改「货主身份由入口决定」相关的账号与入口能力，明确门户建单受货主开关控制

## Impact

- `docs/design/data-model.md`：`sku` 的字段归属重划（`code` 归仓库、`owner_sku_code` 归上游），`owner` 增加接入开关，新增同步相关表。
- `docs/design/interface-map.md`：新增同步接口与权限。
- `docs/design/ui-map.md`：门户建单入口按开关显示；后台增加同步日志页。
- P1 与 P7 的范围受影响：P1 要能接上游下发的主数据，P7 的集成从"只出站"变成"双向"。
