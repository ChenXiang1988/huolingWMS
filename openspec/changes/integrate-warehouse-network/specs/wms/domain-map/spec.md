# Spec Delta

## MODIFIED Requirements

### Requirement: 主数据按「谁的实物知识」分工写入

系统 SHALL 把货品档案的字段按来源分权：上游同步的字段本地只读，货主自建与仓库补充的字段各管一段，三组不重叠。

货品上并存两套编码，属于两个主体、互不覆盖：

| 编码 | 维护方 | 唯一范围 | 用途 |
|---|---|---|---|
| 仓库货品编码 | 本仓 | 全仓唯一 | 库位标签、拣货单、作业沟通 |
| 货主货品编码 | 货主或上游 | 同货主内唯一 | 报文、同步匹配、货主报表 |

#### Scenario: 货主建货品基础信息

- **WHEN** 货主在门户或接口创建货品档案
- **THEN** 可填写名称、规格、单位、分类、重量体积、温区要求、一箱件数、条码与自己的货品编码
- **AND** 不能填写上架优先库区、一托件数、上架要求
- **AND** 仓库货品编码由系统生成，货主不能指定

#### Scenario: 仓库补充存储要求

- **WHEN** 仓管员编辑货品档案
- **THEN** 可填写上架优先库区、一托件数、上架要求
- **AND** 不改变货主或上游维护的字段

#### Scenario: 引用未建档商品

- **WHEN** 建单时引用了本货主下不存在的商品编码
- **THEN** 建单被拒绝并提示先建档
- **AND** 不在建单过程中自动创建商品

#### Scenario: 收货扫到未建档条码

- **WHEN** 收货扫码得到系统内不存在的条码
- **THEN** 该次扫描被拒绝并提示先建档
- **AND** 不自动创建商品档案

#### Scenario: 上游同步的字段本地只读

- **WHEN** 查看一个由上游同步而来的货品
- **THEN** 名称、规格、条码等事实层字段只读
- **AND** 界面明确标示该字段由上游维护
- **AND** 存储属性仍可在本地编辑

#### Scenario: 两个货主用同一个货品编码

- **WHEN** 货主 A 与货主 B 都使用编码 `A001`
- **THEN** 分别建两条货品记录，各自生成不同的仓库编码
- **AND** 不因为编码相同而合并或提示冲突
