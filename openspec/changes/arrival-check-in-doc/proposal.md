# Proposal

## Why

现有入库设计明确把"到货"列为系统盲区：`inbound-walkthrough.md` 写"货到了，系统里什么都没发生，直到仓管开始验货"。对标仓库把"到货签到"作为一道独立工序，车辆到场、月台分配、排队与卸货开始都要在系统里留痕，货量大了还要把签到拆成多个小任务派到不同 PDA。用户已决定签到另建独立单据，不动既有的"到货无感知"入库主链路，本变更按此边界立项。

## What Changes

- 新增能力 `wms/arrival-check-in`：到货签到单据与月台到场登记。
- 签到单据独立于 ASN，通过引用字段关联 ASN 或仓库自建工单，不修改 ASN 的状态机与字段。
- 记录车辆、承运商、司机、预约时段、实际到场时间、月台分配与签到状态；签到后触发验货工序可执行。
- 一张到货单据可按车辆或批次拆成多条签到任务派到不同 PDA。
- 未签到不允许开始验货；已签到未验货的滞留时长可统计。
- **BREAKING**：无。现有 ASN → 收货 → 上架主链路完全不变，签到是并联的可选单据。

## Capabilities

### New Capabilities

- `wms/arrival-check-in`: 到货签到单据能力——车辆到场登记、月台分配、签到状态、签到任务拆分与滞留统计。

### Modified Capabilities

无。不修改 8 份常驻规格；特别是不修改 `wms/domain-map` 关于"验货属入库域收货环节"的既有表述，签到作为独立能力存在。

## Impact

- 新增签到单据表与签到任务，引用 ASN 用 id + code 两字段（D6），不建外键、不改 ASN 表。
- 签到完成事件接 `work-order-process-chain` 的工序完成契约，驱动验货工序解锁；该变更未归档时以契约引用。
- 签到任务派工复用 `task-dispatch-split` 的派单与拆分能力。
- 新增权限标识 `wms_arrival:checkin:*`；新增单号前缀 `CI`。
- 不新增第三方依赖。
