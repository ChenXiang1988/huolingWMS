# Design

## Context

现有入库设计把到货当系统盲区（`inbound-walkthrough.md` 阶段 2），ASN 从 confirmed 直接由仓管点开始收货转 receiving。用户决定签到另建独立单据，不动主链路。规格见 `spec.md`。本设计要解决的是：签到单据如何与 ASN 弱关联、如何驱动验货工序、如何复用派工能力。

## Goals / Non-Goals

**Goals:**

- 定义签到单据与 ASN 的引用关系，确保不改动 ASN 表与状态机。
- 定义签到完成如何触发验货工序解锁而不直接改收货状态。
- 明确拆分与派工如何复用已有能力。

**Non-Goals:**

- 不改变 ASN → 收货 → 上架主链路，不修改 `domain-map` 既有场景。
- 不实现月台调度算法，只记录分配结果。
- 不实现司机端 App，签到由仓管 PDA 或扫码触发。

## Decisions

### 签到单据独立建表，只用 id + code 引用 ASN

D6 要求跨域引用存 id + code、不建外键、不 join 对方表。签到单据与 ASN 的关系是"引用"而非"组成部分"，因此独立建表，存 `asn_id + asn_code`。这样签到可以先于 ASN 存在（车到了还没建单），也不需要改 ASN 表加字段。代价是查询时要单独取 ASN 信息，但签到查询频率低，可接受。

替代方案是在 ASN 上加 `checkin_at` 字段，被排除——那会改 ASN 状态机与表结构，违反"不动主链路"的边界。

### 签到完成发事件解锁验货工序，不改收货状态

签到属于入库前的到场环节，完成后应该让验货工序可执行。做法是通过事件通知 `work-order-process-chain` 的验货工序解锁，而不是直接生成收货单。没有启用工序编排时，签到只留痕，验货仍按原有方式由仓管点开始收货触发——保证不启用新能力时行为零变化。

### 拆分与派工全部复用既有能力

签到任务的按批次拆分与派工不自建机制，直接用 `task-dispatch-split` 的父子任务与派单规则。签到单据只提供任务来源数据和完成汇总。这样签到能力本身很小，只管"到场事实 + 状态 + 引用"。

### 单号前缀 CI，权限独立

签到单据用独立前缀 `CI` 和权限 `wms_arrival:checkin:*`，与入库域的 ASN 权限分开。理由：签到可由月台调度岗位操作，未必有入库预报的建单权限，权限分开才能按岗位授权。

## Risks / Trade-offs

- **签到与验货的耦合窗口**：签到完成事件到验货工序解锁之间若失败，会出现已签到但不能验货。→ 事件带幂等键，以签到单据标识为键；失败可重放，不重复解锁。
- **无 ASN 签到的货主归属**：车到了没 ASN 时，货主信息可能不全。→ 签到单据仍必须绑定货主，由仓管录入；不允许货主为空的签到，避免后续无法归属。
- **月台冲突检测范围**：同一时段同一月台不分配两辆车，但"时段"粒度未定。→ 本变更只定义冲突约束，具体时段长度由仓库配置，留待实施时按实测定。
- **对工单链的依赖**：验货工序解锁依赖工单变更。→ 未启用工单链时退化为只留痕，功能不缺失。
